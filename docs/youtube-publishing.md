# AMP YouTube operating policy

This is the shared production and publishing policy for AMP ads, mathematical
explanations, and recorded tutoring sessions. Every agent reads it before
creating, uploading, scheduling, or editing a video. Use the same policy for
future formats; add a reviewed preset instead of inventing settings per session.

The business outcome is parents discovering AMP, trying it, and buying through
a supported ESA program or another purchase route. Views, subscribers, and
comments help build that audience; qualified trials and purchases establish
whether the funnel works. Teaching must be useful even to a viewer who never
buys. Never promise a universal algorithm trick or a guaranteed result.

For music discovery, production tooling, platform connections, and the broader
daily workflow, start with the [AMP media pipeline](amp-media-pipeline.md).

## Standing decisions

- Upload **private**. Target public release about **24 hours after upload**;
  **12–36 hours** is the normal review window. A render approval is not a request
  for immediate publication. Processing, caption checks, packaging, and a final
  watch-through happen during this window. It is a production standard, not a
  claim that private aging itself boosts ranking.
- Use YouTube's native scheduling for approved organic releases. Keep an
  existing public video public unless Skylar specifically requests otherwise.
  Correct editable mistakes in place. Preserve its URL, views, and engagement.
- **Comments on, everyone may comment, Basic moderation.** Never silently use
  Off, Pause, Hold all, subscriber-only, or members-only. Allow visible like
  counts, embedding, and subscription-feed delivery for organic releases.
- Prepare a useful **pinned comment for every organic video**. Default CTA:
  “Try Adaptive Math Pathways free: https://amp.corpora.inc”. Add one natural,
  topic-specific question when it invites a useful answer. Publish and pin it
  after the video becomes public, then verify it from a viewer's page.
- Generated narration uses only Madeline Brousseaux
  (`XescS24CsOySAkKrLAO3`) or Paul (`J3Ei0Lj6fAobhIqY5ySH`), selected by exact ID.
  Keep natural tutoring audio when it belongs to the recording.
- Target **one video every four hours** and **two Community posts per day**.
  Use one calendar, prepare a buffer, and skip weak material. These are AMP's
  starting operating targets, not platform guarantees.
- Apply these defaults autonomously within an authorized production brief.
  Skylar does not need to reconfirm them for each video. Resolve routine choices
  through the presets and research. Surface a material exception with a concrete
  proposed resolution; do not silently change policy or improvise a new workflow.

## Audience and settings

The channel's commercial audience is parents, homeschool educators, tutors, and
general learners. Its ordinary ads, product demonstrations, adult-facing
tutoring discussions, and general mathematical explanations use **not made for
kids**. A school grade, an approachable explanation, animation, or a child
appearing in a recording does not by itself determine the classification.

Assess the actual video's intended audience and presentation. Content directly
targeting children under 13, including mixed-audience child-directed content,
requires the appropriate classification. Do not change a truthful classification
just to obtain comments. Conversely, do not mark every math lesson made for
kids simply because a fifth grader could use it. Record the audience rationale
in the production brief; inherit a settled series rationale when applicable.
Made-for-kids content cannot provide the ordinary comments/notification funnel,
so identify that exception during planning, before production and upload.
[YouTube audience guidance](https://support.google.com/youtube/answer/9528076).

| Setting | AMP default and verification |
| --- | --- |
| Initial visibility | Private; verify the returned status and Studio |
| Release | Native schedule, normally upload +24h; never an immediate-public upload |
| Comments | On, Everyone, Basic moderation; check the actual video in Studio |
| Likes | Show the number of viewers who like the video |
| Organic notifications | Publish to subscriptions feed and notify subscribers; don't disable this because the initial upload is private |
| Language | English for title/description, audio, and edited captions; use the actual language for other editions |
| Category | Education for lessons/tutoring; a suitable reviewed category for a distinct format |
| Captions | Upload corrected timed captions; verify fractions, notation, proper names, and timing |
| License/embedding | Standard YouTube license; embedding enabled |
| Age restriction | None for ordinary AMP content; classify the actual content accurately |
| AI disclosure | Evaluate actual realistic generated/altered content; record the decision. Do not infer Yes from Blender, an AI-assisted script, or a diagram alone |
| Paid promotion | Evaluate the actual sponsorship/commercial relationship; an upload intended for use in an ad campaign is a separate question |
| Playlist | Required: at least one relevant playlist for every video; verify membership before release |
| Education details | Choose Problem walkthrough for solved examples; add accurate problem timestamps/level where available. Do not invent standards alignment |
| Remixing | Allow owned teaching/product assets; tutoring reuse must match participant permissions |
| End screen | A relevant next video/playlist and Subscribe when eligible, without covering the solution |
| Short | Set a relevant related-video link and a useful selected thumbnail frame; verify the profile's AMP link |

Set browser upload defaults to Private, the AMP free-trial CTA, Education,
English, Comments On/Basic, and visible likes. Keep titles specific to each video.
API uploads must set these explicitly where supported; browser defaults do not
guarantee API behavior.

YouTube's Basic mode holds potentially inappropriate comments while leaving
ordinary comments open. Pinning requires advanced feature access. Private videos
cannot receive comments: write the CTA in advance and post/pin after release.
The Data API does not configure every Studio control or provide a comment-pin
operation; use Studio/browser verification for those steps rather than claiming
an API upload completed them.
[Comments](https://support.google.com/youtube/answer/9483359),
[posting and pinning](https://support.google.com/youtube/answer/6000964).

AI disclosure follows the current platform rule about realistic generated or
meaningfully altered content; it is not a generic “AI helped” checkbox.
Paid-promotion disclosure follows the actual relationship and current policy.
[AI disclosure](https://support.google.com/youtube/answer/14328491),
[commercial relationships](https://support.google.com/youtube/answer/154235).

## Three content lanes

| Lane | Job in the funnel | Production and packaging |
| --- | --- | --- |
| Explanations | Earn search traffic and trust by solving one recognizable problem | State the problem immediately; show the quantities and why each step works; finish when the explanation is complete. No duration quota. Reuse the clean teaching master in AMP; export a separately composed vertical edition |
| Tutoring sessions | Show how real practice, feedback, and teaching work together | Open with a representative learning moment, then supply context. Keep authentic reasoning and useful mistakes. Cut setup/dead time, protect student/account details, add accurate chapters to longer recordings, and extract standalone teaching clips |
| Ads/product demonstrations | Turn demonstrated value into a free trial or an ESA purchase | Show the real product and a specific benefit or supported funding route. Match the spoken promise, landing page, and current offer. Produce a distinct organic cut when useful; keep paid-only variants out of the organic release queue |

Create a brief containing the lane, intended viewer, single promise, exact
problem/benefit, search intent, hook, script/outline, visual model, CTA, audience
rationale, AI-disclosure rationale, formats, playlist, and source rights.
Use an independent reviewer for new mathematical explanations. A render passing
technical checks does not establish clarity or persuasive value.

## Release cadence and production buffer

Run a **four-week operating experiment: one organic release every four hours,
up to six per rolling 24 hours**. Initial local slots are 00:00, 04:00, 08:00,
12:00, 16:00, and 20:00 America/New_York. For the normal schedule, leave at least
four elapsed hours between releases, including daylight-saving transitions. Count all organic
videos, Shorts, live streams, and Premieres against the same channel calendar.

The count and spacing are operating recommendations. Skylar may explicitly
authorize an approved queue drain or another timing exception; record it in the
release receipts and keep the same quality, audience, playlist, and engagement
checks. The lesson scheduler enforces its configured defaults; an authorized
exception does not change its implementation.

Fill slots with distinct useful explanations, teaching clips, tutoring proof,
and product demonstrations. Reserve daytime slots for full explanations and
tutoring sessions when possible. Up to 42 releases a week is capacity, not a
quota. Use roughly six useful teaching/proof releases for each direct product
offer, adjusting from evidence. Funding is one purchase route; lead ordinary
discovery creative with the learning benefit and real AMP experience.

These are initial operating choices, not proven optimal hours. Skip a slot
rather than publish weak material. Keep related landscape/vertical versions
at least 24 hours apart; give each its own opening and composition. Do not dump
ad variants or near-duplicate renders into the feed. Paid-only assets do not
consume organic slots, but their approvals and platform limits still apply.
Check the rolling window across midnight and daylight-saving changes, not just
calendar-day counts. The notification ceiling does not set the publishing cap.

Batch production by visual model and content lane. Maintain a seven-day buffer
of reviewed, rendered packages. Upload each package about a day before its
reserved release; if uploading a batch farther ahead, keep it private and spread
the scheduled releases. Quality failures may extend the private hold. A single
channel calendar owns all formats and all agents; check existing public and
scheduled videos before reserving a slot. Record UTC and the named timezone so
daylight-saving changes do not shift the intended local hour.

YouTube recommends sustainable schedules and batching production. Its limit of
three subscriber notifications per 24 hours is a notification rule, not a
recommendation to publish only three videos or evidence of a ranking penalty
for a fourth. Six spaced releases can exceed notification delivery; accept that
tradeoff rather than restrict useful content to notification capacity. Leave
organic subscription-feed/notification delivery enabled and let the platform
apply its limits. Do not toggle notifications to work around those limits. YouTube reports no correlation between growth in views across
uploads and time between uploads; neither six daily releases nor a specific
hour guarantees growth. Retention, viewer satisfaction, and qualified business
outcomes decide whether to sustain this cadence.
[Scheduling advice](https://support.google.com/youtube/answer/13616979),
[notification limits](https://support.google.com/youtube/answer/7389684),
[performance FAQ](https://support.google.com/youtube/answer/141805).

## Titles, thumbnails, and the first seconds

- Pick one real viewer question. Put the useful topic/promise early in an
  accurate, readable title; keep branding at the end. Prefer a clear title to a
  string of synonyms, hashtags, or unexplained curriculum codes.
- Make the thumbnail communicate one idea at phone size. Use a legible diagram,
  meaningful product detail, or authentic tutoring moment. Avoid tiny full-screen
  UI captures and text that merely repeats the entire title. Design the thumbnail
  while planning the video, not after upload.
- Deliver the title/thumbnail promise immediately. Start with the problem,
  insight, or demonstration; omit long logos and generic introductions. Keep
  captions and labels out of platform controls and away from the math they explain.
- First description lines: the precise value and a useful AMP CTA. Then include
  the worked example or topics, the relevant lesson/program link, chapters when
  useful, and necessary credits/disclosures. Correct automated captions.
- Use only relevant tags, including useful spelling variants, and a few relevant
  hashtags if helpful. Tags are not the primary discovery mechanism. Do not add
  unrelated trending phrases or change titles repeatedly on tiny samples.
- Use native title/thumbnail A/B tests when available and supported by enough
  traffic. Evaluate watch time and the audience reached, not CTR alone.

These choices follow YouTube's guidance on packaging, viewer satisfaction,
search relevance, and retention.
[Recommendation signals](https://support.google.com/youtube/answer/16559650),
[title/thumbnail guidance](https://support.google.com/youtube/answer/12340300),
[A/B testing](https://support.google.com/youtube/answer/16391400).

## Engagement and the ESA funnel

Provide one clear next action. The default pinned comment is:

> Try Adaptive Math Pathways free: https://amp.corpora.inc
>
> Which step would you like to see explained next?

Adapt the question to the video. In a funding-specific video, add the verified
program route and a concise reason to use it. Do not imply universal ESA approval,
invent a funding benefit, or send families to an unrelated generic checkout.
Read the current AMP offer/program configuration before making program claims.
Check the landing page on a phone and preserve the intended free-trial or funded
purchase route. Use consistent per-video campaign tags through AMP's supported
attribution path; keep student or parent information out of URLs and analytics.

For landscape videos, put clickable links in the description and pinned comment.
Shorts description/comment URLs are not clickable: use the profile link and the
Short's related-video link, with a clear spoken/on-screen instruction where useful.
Do not promise “click the pinned link” on a Short.
[Link behavior](https://support.google.com/youtube/answer/13748639).

Use a short next-watch/subscribe end screen only where it helps; don't stretch a
20-second lesson to satisfy a format rule. Eligible videos are at least 25 seconds
long, with end screens in the final 5–20 seconds. Avoid covering the final answer.
[End screens](https://support.google.com/youtube/answer/6388789).

After release, pin the prepared comment, verify it as a viewer, and respond to
useful questions. Heart substantive contributions. Review held comments for
false positives. Never manufacture engagement, post fake praise, buy views, or
answer funding/support questions with invented information.

## Community posts

Schedule **two posts a day**, initially at 13:00 and 21:00 America/New_York.
Posts complement the video calendar and have their own two-post budget. With
six video slots, choose the two strongest conversation opportunities rather
than making six repetitive announcements. Schedule through YouTube's native
post composer and verify the scheduled time or published post URL.

Rotate a short poll, a visual math question, a useful moment from tutoring, and
a follow-up to a released video. Ask one specific question that is easy to
answer. Use an accurate curiosity hook, such as “Why can't you add the
denominators?” or “Screen practice, paper worksheets, or both?” The linked video
must deliver the promised explanation. Avoid misleading clickbait, repetitive
link dumps, generic “thoughts?”, and invented results.

Prepare post copy alongside the video. Link the relevant video when it helps;
use the AMP offer when it fits the conversation. Keep comments open. Respond to
useful answers during a daily comment sweep, and turn recurring questions into
new lessons. Record post impressions, votes, likes, comments, and useful traffic
in the weekly review. Adjust the format from actual response, not notification
delivery. [YouTube post tips](https://support.google.com/youtube/answer/11912631),
[scheduling posts](https://support.google.com/youtube/answer/7124474),
[post analytics](https://support.google.com/youtube/answer/12340301).

## Playlists and channel organization

Every public video belongs to at least one relevant public playlist. Apply this
to the entire back catalog, not only new uploads. Use clear viewer-facing series
for mathematical explanations, AMP product demonstrations, tutoring/practice,
and state-specific funding guidance. Add topic playlists when they provide a
useful learning sequence. Give each a descriptive title, a short purpose and AMP
link, and an order that makes the next watch obvious. Feature the main series
on the channel Home tab.

Assign the playlist while preparing the private upload, then verify membership
after release. Keep paid-only unlisted assets and unreleased production assets
in private operational playlists; adding an unlisted video to a public playlist
can expose it. During the weekly review, find public videos without a public
playlist and assign them. Do not file every video into every playlist.

## Paid-video format and campaign requirements

Every new paid video concept must include the complete Google Ads delivery set:

| Format | Delivery size | Duration |
| --- | --- | --- |
| Landscape, 16:9 | 1920 × 1080 | At least 10 seconds |
| Square, 1:1 | 1080 × 1080 | At least 10 seconds |
| Portrait, 9:16 | 1080 × 1920 | 10–60 seconds for Shorts coverage |
| Feed, 4:5 | 1080 × 1350 | Supplemental feed export; never a substitute for square |

Compose and review each orientation independently from the same source concept.
Keep essential math, product controls, captions and CTA readable at phone size.
Do not satisfy coverage with distorted crops, padded postage-stamp pictures,
or obsolete creative. Preserve exact approved voice IDs, source provenance,
final hashes and per-format review evidence. Larger masters may use the same
ratios; delivery exports must meet at least the sizes above. A short bumper is
an additional placement-specific cut, not the complete delivery set.
[Google Performance Max specifications](https://support.google.com/google-ads/answer/14528532).

Before uploading a new paid concept, run the advertising workbench's
`python3 -m cinema delivery-check delivery.json`. The paid uploader requires
this manifest and verifies actual media geometry, duration, audio and hashes
before authorization or upload requests. Single-format render previews are
allowed; they do not constitute a finished paid delivery. Other compositors
must use the same delivery check. See the
[manifest example](../web/scripts/amp-ads/cinema/README.md#paid-delivery-gate).
Editorial review and platform checks are separate required steps.

Every active Performance Max asset group must have eligible, owned landscape,
square and portrait videos and **Excellent** ad strength. Verify live video IDs,
orientation coverage, policy eligibility and the rating after each campaign
change and in the daily campaign review. Recheck after processing or policy
review; **Pending is unfinished**, not Excellent. Keep serving eligible assets
while repairing gaps. An upload or successful mutation is not proof that the
asset group uses the video or that Google has recalculated its rating.

Resolve all campaign recommendations in the same review. Apply relevant quality,
asset, destination and measurement fixes within the authorized scope. Dismiss
an unsuitable recommendation only after recording its concrete reason and
reading back the resolved state. Preserve approved spend caps, targeting and
conversion goals; a recommendation does not authorize changing them. Record
optimization score and outstanding recommendations from the live account.
The operating target is 100% with zero unresolved recommendations; report any
pending platform update or specific remaining action accurately. Never dismiss
an actionable defect just to improve the displayed score. New recommendations
can appear between reviews, so a receipt records a check time, not a permanent
guarantee.

## Existing videos and paid creative

Apply the editable defaults to the existing library: accurate audience,
comments, pinned CTA, captions, description links, playlist, and next-watch
links. Start with videos receiving paid traffic or meaningful organic views.
Keep public URLs live. A dated video can remain useful as an archive while a
newer video takes its place in advertising.

Review Google Ads video associations weekly. Inventory active campaigns and
asset groups, the exact YouTube IDs they serve, destination pages, impressions,
clicks, spend, and the named signup/purchase conversion actions. Use the account
timezone, verify tracking dates, and allow for conversion lag. Asset-level
metrics overlap and do not establish a video's isolated effect; do not add them
into campaign totals or treat impressions alone as enough evidence of failure.

Prioritize obsolete claims/UI, poor presentation, broken destinations, and
older creative with substantial spend or clicks and no recorded signups after
tracking is working. Prefer a newer, reviewed product demonstration with the
same audience, format, and promise. Lead ordinary discovery ads with AMP's
learning benefit; use EFA/ESA as a relevant purchase route. Preserve useful
state-specific creative for funded audiences.

Install and verify the replacement's eligibility before removing its old
association. Preserve the old resource IDs, metrics baseline, and change
receipt. Keep campaign budgets, bidding, targeting, and conversion goals intact
unless changing them is part of the authorized task. Compare subsequent results
over a meaningful period; newly installed creative is not a proven winner.
[Video asset guidance](https://support.google.com/google-ads/answer/14528532),
[asset-level measurement](https://support.google.com/google-ads/answer/16259414).

## Agent execution contract

1. Read this policy and the content lane's production instructions. Read the
   existing channel calendar and receipts. Reuse the approved preset.
2. Prepare the brief, media, captions, thumbnail, description, pinned comment,
   destinations, and publication slot. Review the actual exports with sound at
   phone size. Validate narration IDs and media hashes.
3. Upload private with the intended channel pinned by ID in private configuration.
   Save the returned video ID, upload time, hashes, and policy version immediately.
   Resume by video ID on retry; do not duplicate an upload after a partial failure.
4. During the hold, verify processed quality, copyright/other platform checks,
   audience, comments/moderation, notifications, caption timing, thumbnail, links,
   playlist, and disclosure decisions. Store a machine-readable check receipt.
   An unknown setting is not a passed check. Complete Studio-only operations in
   Studio. Queue a pin action for release because private comments are unavailable.
5. Schedule the reserved public slot with YouTube. Read back `privacyStatus` and
   `publishAt`; a scheduled video is private until its release. Never call an
   immediate-public upload as a shortcut. Routine settings need no new user vote.
6. At release, verify public playback and comments, post/pin the CTA once, and
   verify the live destinations and related-video/end-screen links. Save evidence.
   A successful upload alone is not a completed release.
7. On failure, retain the artifact and receipt and resume the failed step. Keep
   live videos live while correcting editable settings. Escalate only a concrete
   access failure, material content/audience uncertainty, or unavailable capability.

The lesson uploader at `amp/scripts/publish-lesson-youtube.py` handles media,
captions, thumbnail, receipt, and scheduling. The private release plan records
the browser-verified Studio settings; the uploader cannot independently certify
controls the Data API does not expose. Its tests reject immediate publication,
early release, missing checks, and invalid voice IDs. Do not create an ad hoc
publisher that bypasses this contract.

## Weekly learning loop

Review releases at roughly 48 hours, seven days, and 28 days; use the same age
window when comparing videos. Separate organic from paid traffic and Shorts
from landscape. Track qualified AMP visits, trial starts, supported-program
purchase starts/completions, and cost per acquired customer where paid media is
used. Track impressions/CTR by source, retention/average view duration, engaged
Shorts views, subscribers gained, returning viewers, comments, and next-video
clicks as diagnostic measures. Raw Shorts starts/replays are not the same as
engaged views. [Shorts metrics](https://support.google.com/youtube/answer/10059070).

Choose the next topics from viewer questions, relevant search terms, useful
curriculum gaps, and demonstrated performance. Change one meaningful variable
at a time: topic, hook, packaging, or cadence. A broadening audience can lower CTR
while increasing useful reach. Avoid universal CTR/retention thresholds and
decisions from a handful of impressions.
[CTR interpretation](https://support.google.com/youtube/answer/7628154).

After four weeks, adjust cadence and time using actual audience activity,
qualified conversions, production cost, and retention. Preserve what works.
The goal is a repeatable library and a growing customer relationship, not the
largest count of files or uploads.
