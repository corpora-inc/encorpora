# IAP Affiliate + Discount Codes — Deploy Runbook (0.17.4)

Backend for the affiliate + discount codes feature. Built on `feature/iap-codes`.
This is the exact sequence to take the backend live. Read alongside
`AFFILIATE_CODES_PLAN.md` (the approved spec). The app + native plugin work is
separate (app agent / native agent).

> **Ownership:** Terraform state is local-only and the authoritative machine is
> the DGX Spark (`infra/terraform/README.md`). Do NOT `terraform apply` from a
> machine without the current `terraform.tfstate`, or you will duplicate
> resources. The founder/CTO runs `apply`. App Store Connect / Play Console steps
> are founder-gated.

---

## 0. What this deploy adds

- **DynamoDB single-table `corpan-iap`** (PAY_PER_REQUEST, PITR on, TTL on `ttl`)
  — `iap.tf`.
- **Secrets Manager `corpan/iap/token-signing`** holding the HMAC secret that
  signs `resolutionToken` + `entitlementToken` — `iap.tf` (generated via
  `random_password`; a SEPARATE secret so a terraform write can never clobber the
  out-of-band Apple/Google creds in `corpan/content-packs/verify`).
- **Lambda env vars** `IAP_TABLE`, `IAP_TOKEN_SECRET_ARN`; **IAM** DynamoDB
  read/write + the new secret — `main.tf`.
- **New API routes** `POST /code/resolve`, `POST /entitlement-token`, and the
  legacy alias `POST /affiliate/resolve` (shared handler; no longer fails open) —
  `main.tf`.
- **Lambda logic** (`lambda/*.js`): code classification, token sign/verify, the
  store layer, Apple JWS field capture, Google `subscriptionsv2.get` (with v1
  fallback), idempotent purchase writes, first-verified-touch attribution lock,
  initial + renewal ledger crediting via ASSN V2 / RTDN.

## 1. Terraform apply

```bash
# From the AUTHORITATIVE machine (DGX Spark), with the current tfstate.
cd corpan/infra/terraform

# The `random` provider is new — re-init to fetch it + update the lock file.
terraform init -upgrade

# Review. Expect: 1 new DynamoDB table, 1 new secret + version, 1 random_password,
# 3 new API routes, IAM policy update, Lambda env + code-hash update. NO changes
# to the verify secret's apple/google/cloudfront values (it is untouched).
terraform plan -out iap.plan

terraform apply iap.plan

# Capture the new outputs:
terraform output iap_table_name          # -> corpan-iap
terraform output iap_token_secret_arn    # -> arn:aws:secretsmanager:...:corpan/iap/token-signing
```

If `plan` shows ANY change to `aws_secretsmanager_secret_version.verify` (the
Apple/Google creds), STOP — that secret is populated out of band and must not be
overwritten. Nothing in this change touches it; a diff there means stale state.

### Token secret

The HMAC signing secret is auto-generated by `random_password.iap_token_secret`
and stored in `corpan/iap/token-signing` as `{"tokenSigningSecret":"..."}`. No
manual step. To ROTATE (invalidates outstanding short-lived tokens — they expire
in 5 min / 24 h, so this is safe anytime):

```bash
terraform taint random_password.iap_token_secret
terraform apply
```

> No KMS key is provisioned: the plan permits a secret-derived HMAC, which keeps
> the hot path local (no per-request KMS call). To move to KMS Sign/Verify later,
> swap `tokens.js` `hmac()` for a KMS call and add `kms:Sign/Verify` IAM.

## 2. Seed the registry (LCCLT + partner)

The registry lives in DynamoDB. `lambda/registry_seed.js` defines the launch
seed; `lambda/seed_registry.js` writes it (idempotent overwrites).

```bash
cd corpan/infra/terraform/lambda
npm install   # if node_modules absent (for @aws-sdk/lib-dynamodb)

# Dry run first — prints the items, no AWS calls:
node seed_registry.js --dry-run

# Write for real:
IAP_TABLE=corpan-iap AWS_REGION=us-east-2 AWS_PROFILE=corpan-publisher \
  node seed_registry.js
```

Seeded items:

| PK | SK | Meaning |
|----|----|---------|
| `CODE#LCCLT` | `META` | kind `affiliate+offer`, partner `language-learning-club`, `appleOfferId=lcclt-50`, `playOfferId=annual-lcclt`, `playBasePlanId=annual`, `revenueSharePct=20`, `discountLabel="50% off first year"`, `status=active` |
| `PARTNER#language-learning-club` | `META` | name, payout email, `defaultRevenueSharePct=20`, `status=active` |

To add more codes/partners: edit `lambda/registry_seed.js` and re-run, OR
`PutItem` directly. To pause a code without deleting: set `status: "paused"`
(classifies as unverified, no payout). To change revenue share: edit
`revenueSharePct` on the CODE row (overrides the partner default).

## 3. App Store Connect — Apple offer code for LCCLT (founder)

1. App Store Connect → your app → **Subscriptions** → the subscription group.
2. Select the annual subscription → **Offer Codes** → **+**.
3. Create a **Custom Code** (single shareable alphanumeric):
   - **Code value:** `LCCLT` (matches the registry key, so the partner shares one
     string across platforms).
   - **Reference name / offer identifier:** `lcclt-50` — this is what the receipt
     reports as `offerIdentifier`; it MUST equal the registry's `appleOfferId`
     for `offerApplied` to confirm.
   - **Offer:** e.g. 50% off, 1 year, pay up front (matches `discountLabel`).
   - Redeemable **in app** and via `https://apps.apple.com/redeem`.
4. (Optional, later) Apple-**generated one-time** codes (CSV batches): map each
   batch to a campaign/partner in the registry. The code value differs per user;
   attribution rides on `appAccountToken` + the batch's campaign. Not needed for
   launch — the custom code covers it.
5. **App Store Server Notifications V2:** confirm the production + sandbox URLs
   point at `…/prod/apple-notifications`. The Lambda now credits renewals
   (`DID_RENEW`, `OFFER_REDEEMED`, …) — without this, renewals won't be credited.

> Apple offer fields are on the INITIAL transaction only — never on renewals.
> Renewal attribution rides on `appAccountToken` + our ledger. This is expected;
> the discount naturally ends with the offer period (renews at standard price).

## 4. Play Console — offer + promo for LCCLT (founder)

For a **paid % discount** (what LCCLT is):

1. Play Console → **Monetize → Subscriptions** → the annual product → its base
   plan `annual`.
2. **Add offer** → eligibility = New customer acquisition (or as desired):
   - **Offer ID:** `annual-lcclt` — MUST equal the registry's `playOfferId`.
   - Phase: 50% off first year (matches `discountLabel`).
3. The client re-reads the `offerToken` from `getProducts()` by
   `playOfferId`/`basePlanId` and purchases with it (`purchaseAction.type =
   android_subscription_offer`). The billing layer already honors `offerToken`.

For a **free trial / free unlock** instead (NOT a % discount — Play promo codes
are free-only): create a **promo code** on the base plan; the registry kind would
be `playPromo` and `purchaseAction.type = google_promo_code` (redeemed in the
Play UI / via `https://play.google.com/redeem?code=…`).

**RTDN:** confirm the Pub/Sub topic for Real-time Developer Notifications is
wired to `…/prod/google-notifications`. The Lambda re-reads `subscriptionsv2` on
`SUBSCRIPTION_RENEWED/PURCHASED/RESTARTED` and credits the locked partner via the
obfuscated account id.

### Reporting / manual payout (v1)

```bash
# Sum a partner's month from the ledger (no scans):
aws dynamodb query --table-name corpan-iap \
  --key-condition-expression 'PK = :pk' \
  --expression-attribute-values '{":pk":{"S":"LEDGER#language-learning-club#2026-06"}}' \
  --region us-east-2 --profile corpan-publisher
```

Each `EVENT#<platform>#<txn>` row carries `price`, `currency`, `kind`
(`initial`/`renewal`), `revenueSharePct`. Export → CSV → manual disbursement.
Automated payouts are deferred (plan §9).

## 6. Rollback

- API routes / Lambda code: `git revert` the lambda changes + re-apply (the
  routes are additive; removing them only disables the new feature).
- The DynamoDB table + secret are additive and safe to leave. To fully remove,
  `terraform destroy -target aws_dynamodb_table.iap` (PITR lets you restore).
- The client still works without the backend: with the fail-open removed (app
  agent's change), `/code/resolve` errors surface as "couldn't check — retry",
  and a normal purchase still entitles via the existing receipt path.
