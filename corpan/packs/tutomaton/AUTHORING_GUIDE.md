# Tutomaton — Source-Pack Authoring Guide

This guide is the playbook for adding a new RAG source (per-language corpus, slang pack, dialect overlay, adapter to an external data source) to Tutomaton. Following it produces a Spanish-quality core corpus in ~15-25 hours of focused work.

## What you're building

A **RAG source pack** — a self-contained unit (sqlite + retriever + manifest) that contributes grounding evidence to one or more Tutomaton target languages. Sources are the primitive: Tutomaton's `SourceRegistry` picks them up at runtime, the merge layer composes the LLM's context from whichever are enabled.

Two delivery shapes, same authoring kit:

| Shape | Lives at | Ships how |
|---|---|---|
| **Built-in core** (the per-language authoritative corpus) | `corpan/packs/tutomaton/languages/<code>/sources/core/` | Bundled inside the Tutomaton pack ZIP at the next Tutomaton release |
| **Standalone source pack** (post-ship additions: variants, slang, dialect, medical, the phrase-bridge adapter, any future per-language core authored after the initial release) | Its own directory under `corpan/packs/<id>/` OR `corpan/packs/tutomaton/languages/<code>/sources/<id>/` | Standalone catalog entry; discovered at runtime via `hostApi.discoverPacksByType` |

Both shapes use the same `manifest.json` contract, the same retriever interface, and the same publisher (`tools/llm-packs/publish.py source`).

What a source pack ships:

- `manifest.json` — declares packType, id, target language, authority, priority, file paths
- `data/<x>.sqlite3` — the corpus (gitignored — built by `build_corpus.py`; rebuildable from a clean checkout)
- `retrieval/retriever.ts` — pure TS module exporting `retrieve()` + `resolveTheme()`
- Content-data Python modules (`lesson_data.py`, `theme_data.py`, `l1_errors_data.py`, etc.) that `build_corpus.py` consumes

What a source pack does NOT ship (frontend agent owns these for per-language built-ins):

- `module.json` at `languages/<code>/module.json` — the *language module manifest*, owned by frontend; separate from the *source manifest*.
- `prompts/system_prompt.txt` + `prompts/grounding_instruction.txt` at `languages/<code>/prompts/` — generated by `tools/gen_prompts.py` (frontend).

The pack shell, LanguageManager, SourceRegistry, and chat UI are source-agnostic — they consume your source through the contract.

## Contract reference

Read `corpan/packs/tutomaton/RAG_SOURCES_CONTRACT.md` first. The contract locks:

- Source manifest shape (§1)
- Where sources live (§2)
- Retriever module exports + the **object-row** access pattern (§3 — `row.colname`, NEVER `row[0]`; the positional bug already shipped once, do not repeat)
- Merge rules and theme-bypass authority (§4)
- Discovery + per-language enable prefs (§5)
- Universal sources via `tutomatonLanguage: "*"` (§7 — applies to the phrase-bridge case)
- Non-authoritative grounding framing (§8 — `<reference type="canonical">` vs `<reference type="inspiration">`)
- Catalog publishing convention (§9)
- ID naming convention (§10 — `tutomaton-corpus-<code>-core-v1`, `tutomaton-corpus-<code>-<variant>-v1`, `tutomaton-<adapter>-v1`)
- Migration policy (§11 — no shim, atomic)

## Quality bar (for per-language `core` sources)

Every core source ships at Spanish-parity minimum:

- **~35 lessons** of ~400-600 words each (~14-21K words of authored content)
- **25 themes × ~30 items** = ~750 vocabulary items with IPA + L1 translations
- **5K-10K word lemmas** (from kaikki Wiktionary, filtered by frequency)
- Optional but high-ROI: **L1-error patterns** for ~3 L1 cohorts × ~50 errors each
- Optional language-specific tables (phrasal verbs for English, classifiers for Mandarin, kanji for Japanese, roots + broken plurals for Arabic, etc.)

Seed-level (10 lessons, 10 themes) is **not acceptable** for shipping. Variant sources (slang, medical) can be much smaller.

## The seven phases

### Phase 1: Scaffold (~5 minutes)

```bash
cd corpan/packs/tutomaton
python3 scripts/bootstrap-language.py <code> <Name> <Native> <voice-code>
# Example: python3 scripts/bootstrap-language.py hi Hindi हिन्दी hi-IN
```

Creates `languages/<code>/sources/core/` with stubs for every file you need. Generates the source manifest with `id: tutomaton-corpus-<code>-core-v1`, `authoritative: true`, `priority: 100`.

The scaffolder does NOT touch `languages/<code>/module.json` or `prompts/` — frontend's territory.

### Phase 2: Get the inputs (~30 minutes)

Download the kaikki Wiktionary dump for your target language:

```bash
mkdir -p ~/data/kaikki
curl -fL https://kaikki.org/dictionary/<Name>/kaikki.org-dictionary-<Name>.jsonl \
  -o ~/data/kaikki/kaikki-<code>.jsonl
```

For languages with specialized data sources, fetch those too (CMU dict for English, HSK lists for Mandarin, JLPT lists for Japanese, three-letter-root tables for Arabic, etc.). Cache under `~/data/<lang>_rag/`. Build script paths configured in `build_corpus.py`.

### Phase 3: Author the lessons (~8-12 hours)

Open `languages/<code>/sources/core/lesson_data.py`. The template includes 30 universal lesson stubs. Author each at reference-grade depth (~400-600 words). Add language-specific lessons for what's unique:

| Language family | Must-haves |
|---|---|
| Romance | ser_vs_estar (or equivalent), preterite vs imperfect, subjunctive triggers |
| Germanic | strong/weak verbs, modal particles (DE), separable verbs (DE) |
| CJK | tones (ZH), classifiers (ZH/JA), kanji_readings (JA), 把/被 (ZH), particles (JA) |
| Slavic | aspect_perfective_imperfective, case_system, motion_verbs (RU) |
| Semitic | three_letter_roots, broken_plurals, mood_jussive (AR) |
| Agglutinative | vowel_harmony (TR/FI), case_suffixes (FI/HU/KO), polite_speech_levels (KO/JA) |

Style guidance:

- Lead with the rule, then 2-3 short examples, then a common-mistakes callout.
- Tables work for ≤4 columns; wider tables wrap awkwardly.
- Don't write h1 headers in the body (the title renders separately).
- End lessons with `**Related**: [[topic_slug]]` if you have cross-links not already in the `related` field.

### Phase 4: Author themes + word lemmas (~3-5 hours)

`theme_data.py` — fill in all 25 themes with ~30 items each. For each item supply:

- `word` (target-language form with proper script/diacritics)
- `ipa` (recommended; can pull from kaikki at build time if skipped)
- `l1` dict for `{en: "..."}` plus your top 4-5 L1 cohorts

Themes deliver canonical vocabulary lists — these get returned DIRECTLY by the registry's theme-bypass path (no LLM call), so curate ruthlessly.

`build_corpus.py` pulls the top 8000 word lemmas from kaikki automatically. For noisy top-frequency words, hand-curate overrides in `_source/core_vocab.json`.

### Phase 5: L1-aware errors (~3-5 hours per L1, optional)

The killer differentiator. Open `l1_errors_data.py` and author ~50 errors per L1 cohort you target. Each error needs:

- `error_pattern`: regex matching the typical mistake (be conservative — false positives are worse than misses)
- `correct_form`: what they should have said
- `l1_explanation`: in the L1, in L1 script
- `en_explanation`: same in English (fallback)
- `example_wrong` / `example_right`
- `severity`: high / med / low

Pick L1s by ROI. For English target: Spanish, Chinese, Japanese, Korean, French, Portuguese, German, Russian, Arabic, Hindi. Pick 3 to start.

### Phase 6: Build the sqlite (~30 seconds)

```bash
cd languages/<code>/sources/core
python3 build_corpus.py
# → writes data/<code>.sqlite3 + reports row counts
```

Write a `test_retriever.py` (recommended) that loads the sqlite, runs canonical queries through your `retriever.ts`'s SQL paths (port to Python; trivial), confirms the right kind/lesson comes back.

### Phase 7: Publish

```bash
cd corpan   # repo root
python3 tools/llm-packs/publish.py source \
  packs/tutomaton/languages/<code>/sources/core \
  --upload
```

The publisher:

1. Reads `sources/<id>/manifest.json` to learn id, target language, file paths
2. Builds `<id>.zip` containing the entire source directory
3. If `--upload`: uploads to `s3://corpan-prod/artifacts/corpan/tutomaton-sources/<id>.zip`
4. Prints the registry entry: `{id, packType, name, tutomatonLanguage, authoritative, priority, ..., url, sha256, sizeMb}`

**Hand the printed registry entry to the frontend agent.** Per `[[manifest-owned-by-frontend]]`, Spark never edits `packs/tutomaton/manifest.json` or the catalog. The frontend agent pastes the new source's metadata into:

- The Tutomaton manifest (if this is a built-in core source bundled in the next Tutomaton release)
- The catalog entries[] (if this is a standalone source pack discovered at runtime)

## Content-version bumps

Per contract §1 + §10: source `id`s are irreversible — never reuse for different content. To publish an updated corpus, bump `-v1` → `-v2` in the source's `manifest.json` (and the `id` literal inside `build_corpus.py` if it appears anywhere). Republish; the new ZIP coexists with the old.

The frontend agent handles the catalog cutover (point users at `-v2`; eventually GC `-v1`).

## Repeatable cost per language

| Activity | Hours |
|---|---|
| Phase 1: scaffold | 0.1 |
| Phase 2: data fetching | 0.5 |
| Phase 3: lessons (35 × ~12 min each) | 7 |
| Phase 4: themes + words | 4 |
| Phase 5: L1-errors (per L1, optional) | 4 |
| Phase 6: build + test | 1 |
| Phase 7: publish + handoff | 0.5 |
| Language-specific code/schema | 2-4 |
| **Total per language** | **~15-25 hrs** |

For 50 languages at this rate: ~750-1250 hours. Bounded, parallelizable across contributors, every shipped source compounds the pack's value. Each new source is a catalog-only release — no Tutomaton runtime release.

## Tips for high-quality output

- **Don't paraphrase Wikipedia.** Lessons should be original, learner-focused, example-driven.
- **Pick examples that survive translation.** "I am 25 years old" works in 30 languages; "I'd really go in for a cup of tea" doesn't.
- **Calibrate to CEFR**:
  - A1: present tense + 500 most-common words
  - A2: past + future + 1000 words
  - B1: perfect aspects + conditionals + 2500 words
  - B2: subjunctive + advanced syntax + 5000 words
- **L1-error severity matters**: `high` triggers gentle correction tone; `low` is a "by the way" note. Don't over-flag — that's nagging.
- **Themes are canonical lists** (the registry bypasses the LLM for theme hits, per contract §4). Every word in your theme list is what the user sees. Curate ruthlessly.
- **Non-authoritative reference markdown** (slang packs, the phrase-bridge): write in a "useful example" voice, NOT a "this is the answer" voice. Per contract §8 the registry will label your reference `<reference type="inspiration">` and the LLM is told to treat it as material to riff on, not gospel.

## Reference packs

- `corpan/packs/tutomaton/languages/es/sources/core/` — the gold standard. ~35 lessons, ~25 themes × 30 items, 522K verb rows.
- `corpan/packs/tutomaton/languages/_template/sources/core/` — the empty scaffold (do not edit; this is what `bootstrap-language.py` copies from).
- `corpan/packs/tutomaton/languages/en/sources/core/` — first migrated source with full L1-errors (es/zh/ja) + phrasal_verbs table.
- `corpan/packs/tutomaton/languages/ar/sources/core/` (once authored) — premium-quality Arabic corpus + Arabic-specific tables (roots, broken plurals, verb forms).
- `corpan/packs/tutomaton-phrase-bridge/` (once authored) — the universal-source pattern: `tutomatonLanguage: "*"`, no sqlite, queries `hostApi.phrasePacks` + `queryPackDb` at runtime, returns inspiration grounding for any active target language.
