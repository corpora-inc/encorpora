# Spaces

Everyone in AMP is in one **space** at a time. The space decides the frame, the navigation, the words and what a screen composes. It never decides a permission: the server authorizes every request exactly as it would without spaces, and nothing a space shows may offer an action the server would refuse.

| Space       | Who                                                                                                                   | Where                                                                        | Home                                             |
| ----------- | --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------ |
| `family`    | a family's account holder, its second parent, a co-teacher of a family's class; their children on the parent's device | `/school/<family org>/classes/<class>/…` today; `/family/<family>/…` from P2 | the family's Today                               |
| `classroom` | a teacher, aide, co-teacher, or a viewer or admin inspecting a class                                                  | `/school/<org>/classes/<class>/…`                                            | the class's Today                                |
| `school`    | a school, network or district admin or viewer                                                                         | `/school/<org>/…`                                                            | Overview, or the one class of a one-class school |
| `me`        | any adult, about themselves, and practice as a profile                                                                | `/me/…` and the shared learning screens for their own learner                | Levels (`/me`)                                   |
| `student`   | a child in a student session                                                                                          | `/practice`, `/join`, `/c`, `/standings`                                     | practice                                         |
| `account`   | any adult: their account, setup, the starter and payment steps                                                        | `/account/…`, `/start/…`, `/school/start` …                                  | Account (`/account/security`)                    |
| `public`    | anyone: public pages, and links that carry their own authority                                                        | `/schools`, `/sign-in`, `/p`, `/school/invite`, `/family/approve` …          | —                                                |

Tutoring is not a space: an existing tutoring class is a family-kind org and resolves to `family` with the `co-teacher` or holder relationship. Practicing at a level is `me`.

## Resolution

`resolveSpace(match, session, resources)` (`src/web/features/spaces/resolve.ts`) is the one description of where the person is. It is pure: the same inputs always describe the same frame. `useSpace` (`useSpace.ts`) feeds it from the settled route and the queries the route already loaded; `AppShell`, `Tabs`, the drawer and the place switcher render from what it returns, and nothing else reads "the current place".

- **match**: the settled route's address, its search, the learner it names (`$learnerId`) and its static `space` (`staticData.space` on every typed route, `spaceOfPath` for the legacy catch-all; a test keeps the two in agreement). Classroom and school routes resolve to `family` when the org they name is a family's.
- **session**: `none`, `student` or `adult`. A student session always wins (`auth.ts`): a parent's cookie on the same device never brings the parent's chrome. A verified staff sign-in that replaces a student session arrives as an adult session; the resolver never decides that.
- **resources**: the org, its classes, the class's year and its practice coverage, as the server returned them for this account. `undefined` is not yet answered; `null` is refused, missing or failed.

The result is a discriminated union, one shape per space:

| Space       | Carries                                                                                                                                                                                                                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `public`    | `entry`: `page`, `invite`, `approval`, `buyer` or `student-entry`                                                                                                                                                                                                                          |
| `account`   | `scope`: `settings`, `setup`, `starter` or `steps`                                                                                                                                                                                                                                         |
| `student`   | `status` and the student's own learner                                                                                                                                                                                                                                                     |
| `me`        | `status` (`unavailable` when the address names a learner this account doesn't read), `mode` (`own`, `profile`, `none`), the adult's own learner or profile                                                                                                                                 |
| `family`    | `status`, the family id (its org; null only for a learning screen of an owned child hosted in another family's class, until P2's family projection names it), the `relation` (`holder`, `second-parent`, `co-teacher`), its class, its own children, the chosen child, target capabilities |
| `classroom` | `status`, the org, the class (`past`, `board`, `start`), how this person reaches it (`teacher`, `aide`, `viewer`, `admin`, `staff`), target capabilities                                                                                                                                   |
| `school`    | `status`, the org, target capabilities                                                                                                                                                                                                                                                     |

Every shape also carries the bar (`tabs`, `practice`, `plain` or none), the tabs and the open one, the bar's actions, the drawer's destinations, the bar's place name and the space's words.

"Once per settled route" means a render snapshot, never a cached grant:

- Every query is keyed by the account and the resource; a `/me` for another account, or an org or class answer for another id, is never read.
- **Session identity.** A session is its account and its token. When a session ends or is replaced (sign-out, another account, or the same account signed in again with a new token), its token is retired (`lib/session-generation.ts`): `request` refuses a retired token when a request is asked and again when it answers, so an old loader that resumes after the change can neither ask with the old session nor write its answer where the new one reads; the token becomes current again only if the session itself returns (a parent's, after a child's handover). For the same account, `retireSession` (`lib/query.ts`) also cancels the old session's in-flight requests and removes its cached answers, and `providers.tsx` remounts every screen, so no mounted screen keeps the old session's answers or actions (a staff screen's invite form included). While the same place is asked again in the same session, `AppShell` keeps its last ready frame (`hold.ts`, keyed by the session identity); another session, another place or a refusal never shows an old frame or its actions.
- **Refusals and failures.** A refused answer (401, 403, 404) is `unavailable`; a refused `/me` leaves no relationship. A lookup that failed without a refusal is `failed`, and so is a place whose session has no `/me` at all because it failed (a new sign-in whose account didn't load). Practice coverage whose lookup failed counts as none, so Start class is not offered on a stale answer.
- **The content guard.** An `unavailable` or `failed` space keeps the screen itself out: `AppShell` renders "This isn’t available to your account" (with the way to the person’s places) or "This didn’t load" (with Try again) in its place, so nothing of that screen renders or asks the server, including a learning screen whose named learner was removed while it was open.
- **Only the screen on view chooses.** The shell (`useSettledMatch`), the learning view and practice (`useAddressedIdentity`) read pathname, parameters and search from one snapshot: the displayed route's own matches, never the address still loading. Route guards never change this device's learner (a guard also runs for preloads and for navigations that never show); the shell makes the displayed screen's learner the device's choice once it is on view (`committedChoice`). A navigation still loading, or abandoned, changes nobody.

### Capabilities

Capabilities are the server's, named by target: `{ target: { kind: "org" | "class" | "learner", id }, can }`.

- **Org:** `can` from `GET /orgs/:org`.
- **Class:** `GET /classes/:class/year` returns the class's org, the path of orgs above it, its name and `can`, all decided by the same `can` as every route. The resolver frames a class only when the org the route names is on that path; an answer without a path proves nothing and stays unresolved (no tabs, no actions). A class's tabs are exactly what its `can` allows (each tab's screen asks: Today, Map, Time and Students `students.read`; Grades and Report cards `grades.read`; Workbooks `workbooks.read`; Settings `settings.read`), and Start class needs `signin.read`. A role held from above (a district's admin or viewer) is read from what the server allows there, never from a role label at this org.
- **Learner:** from the server's `/me` projection of whose the learner is and their access, never from a space: `learner.read`; `learner.practice` where the server says they may practice here (`canPractice`); `learner.handover` for a second parent's children (practice from the family's Today); `learner.name`, `learner.consent` and `learner.purchase` for the account holder's own children only. The family drawer offers "Let … practice" only with `learner.practice`.

## Shell

- **Bar**: the logo, the place's name ("Grade 4 Math · Alder Grove", "Pell family", "My practice", or the child whose record a learning screen shows), the space's tabs, and its actions. Below 1024 px the tabs take a row of their own.
- **Tabs** (`tabs.ts`), measured to fit at every width; what does not fit goes under More, the open tab always shown.

| Space            | Phone                               | More                                                                                                       |
| ---------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Family           | Today, Map, Workbooks, Time         | Report cards, (Grades for a group of more than six), People, Settings                                      |
| Classroom        | Today, Map, Grades, Students        | Time, Workbooks, Settings                                                                                  |
| School           | Overview, Classes, Staff, License   | Calendar, Privacy, Activity, Settings, Integrations (each by capability); district and network add Schools |
| Me               | Practice, Levels, Workbooks         | Pathways, Inventory, Profiles                                                                              |
| A child's record | Overview, Pathways, Inventory       | —                                                                                                          |
| Account          | Sign-in, Learners, Billing, Privacy | —                                                                                                          |

- **Drawer**: the space's own destinations (and in a family, which of its children), then the place switcher, then the account. It never shows another space's learners or destinations.
- **Place switcher**: one bounded request, `GET /api/v1/school/places` (`src/schools/places.ts`): the orgs this account holds a staff role at, the schools below a district it oversees, and the classes it teaches or aides this year, each list stopping at 40 with `more` set. Grouped as **Family** (their own, second-parent families, co-teaching), **Teaching** (each school with its role, its classes, viewer and aide included) and **My practice** (their own, Practice at a level). Six teaching places show before "More places"; past the server's limit, "All your schools" opens `/school`. Choosing a place lands on its home, chooses a learner who belongs there (none for a class or school), and remembers it for `/` only.

## Vocabulary

`spaceWords(space)` (`words.ts`) is a typed table of every noun that differs by space: the learner and learners, whose names a sign-in list shows, the group, the people screen, a map key's own-grade line, how sign-in is introduced, the switcher's heading and the tab row's name. Shared widgets take these as props; a family never reads "student" and a class never reads "your children".

`scripts/check-space-boundaries.ts` (part of `npm run lint:navigation`) fails when a shared module (`src/web/ui/**`, ClassMap, ProgressRecord, the grade parts, Feed, WeekFacts, SignInCode, JoinClass, CodeTiles, the pathways Graph, WorkbookList, AllowancePause, PracticeWorkspace) branches on an org kind or a space, takes a `family` flag, reads the account's places, or imports the resolver, the shell's navigation, onboarding's place logic or the second-parent API. Server-produced copy (Today's tasks, report cards and PDFs, activity) is part of each space screen's composition contract, reviewed with the screen.

## Returns

One contract for coming back to a place: `appReturn` (`src/web/features/spaces/returns.ts`). "Add a place" and every step of the starter use it now (`?from=`, carried between `/start/…` steps by `carriedKeys`, with Cancel on every step, and onto the teacher's `/school/start`, whose Back becomes Cancel to the same place, and whose confirmation email's link returns to `/school/start?from=…`); every family redirect in P2 uses it, and the older returns move onto it then: the root's and a school sign-in's `next` (300 characters, `safeSchoolPath`) and `/continue`'s memory (500, `safeReturnPath`).

| Rule         | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Form         | a path inside this app, normalized by `returnTarget`: one leading slash, never another origin, `//`, `/\`, `/api`, or control characters                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Length       | at most 2,048 characters (`RETURN_LIMIT`); a longer result keeps the path alone                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Destinations | an allowlist of the app's places (`PLACES`): `/school/<org>/…`, `/family/<family>/…`, `/me` and its profiles, the learning screens, a learner's workbooks, `/account/security                                                                                                                                                                                                                                                                                                                                                                                                                                                                | billing | privacy/…`, `/family` and its learners. Any other address returns nothing |
| Refused      | anything `public` or a student's (an invitation, approval, buyer's link, `/p`, `/join`, `/c`), and first-run and payment steps (`/start`, `/continue`, sign-in and sign-up, `/purchase`, `/invoice`, `/consent`, `/access`, `/school/new`, `/school/start`, `/school/connect`, `/school/adopt`): the caller goes to its own home                                                                                                                                                                                                                                                                                                             |
| Search kept  | the list view keys (`VIEW_KEYS`), `open` (rewritten through `readStack`/`writeStack`: at most 1,000 characters and five valid layers of a registered kind, else dropped), `skill`, `learner`, `profile`, `class`, `term`, `week`, `student`, `to`, `devices`, `section`, each at most 200 characters; `from` as a date (Time's range) or as a practice profile's own return, itself checked by these rules one level deep (never a nested secret); every other key is dropped. A settings section is `?section=`, never a fragment. P2 registers the `child:<learner>` layer kind in `nav/entities.ts`, so family layers pass the same check |
| Fragment     | always dropped: a fragment is where a link's secret lives                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## Continuations

Every entry keeps working and lands in the right space. A link's secret travels only in a fragment and is taken out of the address before the router or any return can read it:

- `/c#…` and `/join/continue#…`: `card-entry.ts`; `/p#…`: `share-entry.ts`;
- `/school/invite#…` and `/family/approve#…`: `capability-entry.ts` takes the fragment and replaces the address, and holds the link in this page's memory only, for two hours (checked on every read). Nothing is written where another tab, a tab this one opens, a reload or another page could read it: a reloaded tab has nothing held, and the person opens the link from the email again. The one deliberate carry is a sign-in the person starts from the link, which the screens keep on the device (`rememberInvite`, `rememberApproval`). A link that is over (used, expired, ended) or that the server refuses (4xx) is let go, held and carried alike; a passing network failure is not. `forgetEveryLink` (`features/links/forget.ts`) lets every held and carried link go when an account signs out or changes (a sign-in from no account keeps the link that started it) and when a student's session begins or ends on the device. A fragment opened later inside an already-loaded page is read by the screen from the address as before; no return ever carries it (`appReturn` drops fragments);
- `/schools/continue#token=…` and `/school/adopt#token=…`: `capability-entry.ts` runs `prepareBuyerHandoff` and `prepareSchoolAdoption` at boot (their route guards run them again, harmlessly).

A secret never goes into `next`, `from`, analytics or a forwarded hash.

Today, until P2: `familyEquivalent` (`app/school-routes.tsx`) sends the org-level leaves to the family class's Today, People, Map or Settings, choosing the first class the person can read and carrying `open` only. P2 replaces it with the table above.

**Person and learner layers.** Class layers name a roster **person** (`student:<person>`, `work:<person>.<attempt>`, `nav/entities.ts`); family layers will name a **learner** of that family (`child:<learner>`). The mapping is the family projection's: each of the family's children carries its learner id and, where one exists, its person id in that family's class. An old person layer resolves to the child whose person id it is, in the named family only; a person who is not one of that family's children drops that layer (the page and the layers beneath stay), never opens another child. `LayerHost` receives the family as its scope, so a family layer never asks a class's endpoints.

## Learning screens

`/overview`, `/progress`, `/practice`, `/pathways`, `/inventory`, `/lessons/…`, `/books/…` and `/learners/$learner/workbooks/…` name their learner, in one order everywhere: `$learnerId`, then `?profile=` (with its `from`), then `?learner=`. `carriedKeys` (`features/profiles/practice-mode.ts`) carries a profile or a learner between learning screens, never both, and a destination that names its own replaces it. `addressedIdentity` (`features/spaces/identity.ts`) reads that identity; loaders load it, the learning view and practice show it, and nothing falls back to another learner when it is missing. `adoptPracticeMode` only checks it: a learner or profile this account doesn't read stops the screen with a permission error, and no guard changes this device's choice. Once the screen is on view, the shell makes the named learner the device's choice (`committedChoice`), so unnamed screens follow. A learner removed while their screen is open is nobody: the content guard replaces the screen. A refresh, Back or a second tab keeps that person. Moving from a family to My practice changes the address, never just the device's choice.
